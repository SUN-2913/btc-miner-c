# btc-miner-c

CPU-майнер Bitcoin для **соло**-пулов на C с рукописным x86-64 ассемблером.
Клиент Stratum v1, три движка хеширования, автовыбор движка по замеру
на том числе потоков, которое вы реально задали.

**Вшитого пула нет. Вшитого адреса вознаграждения нет.** Оба параметра
обязательны в командной строке. Майнер не работает ни на кого, кроме вас.

[English version](README.md)

## ⚠️ Сначала прочитайте: это лотерея, а не заработок

Хешрейт сети Bitcoin — порядка 10²¹ H/s. Быстрый десктопный CPU со всеми
оптимизациями этого проекта выдаёт около 10² MH/s, то есть примерно
**10⁻¹³ от сети**.

Что из этого следует:

- **Найти блок**: среднее ожидание измеряется миллионами лет. Теоретически
  может выпасть и на первом хеше, но планировать это нельзя.
- **Найти шару**: у solo.ckpool.org минимальная сложность шары 10 000.
  При ~90 MH/s это одна шара примерно раз в 5 суток, при ~200 MH/s — раз в 2.5.
  Пока первая шара не принята, веб-статистика пула будет пустой.
- **Шары на соло-пуле не оплачиваются.** Это только индикация. Деньги приходят
  только за найденный целиком блок.
- **Электричество не бесплатное.** Шесть потоков под AVX2 — это примерно
  +60–80 Вт к простою. Посчитайте по своему тарифу, прежде чем оставлять 24/7.

Проект существует ради изучения микроархитектуры CPU — SHA-NI, AVX2
multi-buffer, масштабирование SMT, гибридные P/E-ядра — и ради очень дешёвого
лотерейного билета. Так к нему и относитесь.

## Возможности

- **Три движка**, все с оптимизацией midstate:
  - `shani` — рукописный x86-64 ассемблер на инструкциях SHA-NI
  - `avx2` — 8 nonce параллельно в 8×32-битных lanes AVX2 (multi-buffer)
  - `scalar` — переносимый fallback на C для любого x86-64
- **Midstate**: первые 64 байта заголовка хешируются один раз на задание /
  extranonce2, поэтому горячий цикл делает 2 сжатия SHA-256 на nonce вместо 3.
- **Автотюнинг на вашем числе потоков**: при старте каждый доступный движок
  замеряется ровно на `-t N` потоках, побеждает быстрейший. Это важно:
  победитель меняется с числом потоков (см. замеры ниже).
- **Self-test по эталонным векторам** до начала майнинга. Если движок считает
  неверно — программа завершится, а не начнёт слать пулу мусор.
- **Однострочный живой статус** — без спама в консоли. Наверх печатаются
  только значимые события.
- **Отслеживание best difficulty** — прогресс виден даже без шар.
- **Детектор блока**: расшифровывает `nbits` в сетевой target, при попадании
  печатает баннер и складывает дамп в `BLOCK_FOUND.txt`.
- **Задержка старта** (`-d`) для автозапуска: дождаться, пока ОС успокоится,
  и только потом мерить. Процессор в это время не используется.
- **Ограничение потоков** (`-t`), чтобы машиной можно было пользоваться.
- Полный Stratum v1: subscribe, authorize, notify, set_difficulty, submit,
  vardiff, clean jobs, автоматический реконнект.
- Никакой телеметрии, автообновлений, доступа к кошелькам и приватным ключам.
  Соединение только с тем пулом, который вы указали.

## Требования

- Любой x86-64 CPU. SHA-NI и AVX2 определяются в рантайме, не обязательны.
- GCC и binutils с поддержкой SHA-NI.
  - Windows: MSYS2 **UCRT64** / MinGW-w64 (`pacman -S mingw-w64-ucrt-x86_64-gcc make`)
  - Linux: `gcc`, `make`, `libpthread`
- MSVC **не поддерживается** (синтаксис GNU-ассемблера и `unsigned __int128`).
- Bitcoin-адрес и адрес Stratum-пула.

## Архитектура

Если открываете код впервые — начните с [ARCHITECTURE.ru.md](ARCHITECTURE.ru.md):
модель потоков, путь данных от JSON пула до хеша, суть midstate и почему выбор
движка замеряется на вашем числе потоков.

## Сборка

```bash
# Windows (оболочка MSYS2 UCRT64)
gcc -O3 -msha -msse4.1 -o btc-miner-c.exe src/miner.c src/sha256ni.S -lws2_32 -lm

# Linux
gcc -O3 -msha -msse4.1 -o btc-miner-c src/miner.c src/sha256ni.S -lpthread -lm

# или просто
make
```

AVX2-часть компилируется через локальный `#pragma GCC target("avx2")`, поэтому
глобальный `-mavx2` не нужен и бинарник запускается и на старых CPU.

## Использование

```
ОБЯЗАТЕЛЬНЫЕ
  -a ADDR        Bitcoin-адрес вознаграждения (без значения по умолчанию)
  -p HOST:PORT   адрес Stratum-пула (без значения по умолчанию)

НЕОБЯЗАТЕЛЬНЫЕ
  -w NAME        суффикс воркера, добавляется к адресу (по умолчанию: cpu1)
  -t N           число потоков (по умолчанию: все логические CPU)
  -x PASS        пароль пула (по умолчанию: x)
  -e ENGINE      auto | shani | avx2 | scalar (по умолчанию: auto)
  -d MIN         задержка старта в минутах, можно дробные (по умолчанию: 0)
  -h             справка
```

Имя пользователя Stratum собирается как `АДРЕС.ВОРКЕР`. Выплата уходит на
`АДРЕС`; суффикс воркера — только метка для статистики пула.

### Примеры

```bash
# минимум
btc-miner-c -a bc1qвашадрес... -p solo.ckpool.org:3333

# оставить машину рабочей: 6 потоков
btc-miner-c -a bc1qвашадрес... -p solo.ckpool.org:3333 -t 6

# автозапуск: подождать 5 минут после загрузки, затем тюнинг и майнинг
btc-miner-c -a bc1qвашадрес... -p solo.ckpool.org:3333 -t 6 -d 5 -w desk

# принудительный движок (тюнинг пропускается) — удобно для замеров
btc-miner-c -a bc1qвашадрес... -p solo.ckpool.org:3333 -t 8 -e avx2
btc-miner-c -a bc1qвашадрес... -p solo.ckpool.org:3333 -t 8 -e scalar
```

### Несколько машин

Используйте один адрес с **разными суффиксами воркеров**, чтобы различать их
в статистике. Одинаковые суффиксы тоже допустимы — пул суммирует хешрейт и не
отключает дубликаты, — но тогда не видно, какая машина отвалилась.

```bash
btc-miner-c -a bc1qвашадрес... -p solo.ckpool.org:3333 -t 6  -w i7
btc-miner-c -a bc1qвашадрес... -p solo.ckpool.org:3333 -t 10 -w i9
```

### Автозапуск в Windows

`Win+R` → `shell:startup` → создайте ярлык:

```
Объект:          "C:\путь\до\btc-miner-c.exe" -a bc1qвашадрес... -p solo.ckpool.org:3333 -t 6 -d 5 -w desk
Рабочая папка:   C:\путь\до
Окно:            свёрнутое в значок
```

Рабочую папку укажите явно — `BLOCK_FOUND.txt` пишется в текущий каталог процесса.

## Вывод программы

```
[cpu] Intel(R) Core(TM) i7-10700F CPU @ 2.90GHz
[cpu] SHA-NI: no | AVX2: yes | threads: 6
[tune] benchmarking on 6 thread(s), 0.35 s per engine...
[tune] scalar :     8.24 MH/s
[tune] avx2 x8:    52.71 MH/s
[tune] selected: avx2 x8 (52.71 MH/s)
[cpu] engine: AVX2 x8 multi-buffer + midstate
[selftest] OK (reference vectors, x8 lanes)
[net] connected
[pool] authorized
[00:02:15] 52.70 MH/s   | 7.11G     hashes | A/R 0/0 | diff 10000 | best 1.65 | job 6aff9dca
```

Последняя строка обновляется на месте. Поля:

| Поле | Значение |
|---|---|
| `[hh:mm:ss]` | время работы |
| `MH/s` | сглаженный хешрейт |
| `hashes` | всего вычислено двойных SHA-256 |
| `A/R` | шары приняты / отклонены пулом |
| `diff` | текущая сложность шары от пула |
| `best` | максимальная сложность среди найденных хешей |
| `job` | текущий id задания (обрезан) |

`best` растёт примерно как `всего_хешей / 2³²`. Когда он достигает `diff`,
отправляется шара. Отклонённая шара обычно означает «stale» (пул сменил задание,
пока шара летела) — несколько процентов нормальны.

## Замеры

Реальные прогоны этого кода, движок задан принудительно через `-e`:

| CPU | Движок | Потоков | MH/s |
|---|---|---:|---:|
| i7-10700F (без SHA-NI) | scalar | 8 | 11.0 |
| i7-10700F | avx2 x8 | 8 | 70.4 |
| i7-10700F | avx2 x8 | 16 | 91.4 |
| i9-12900KF | shani | 8 | 85.6 |
| i9-12900KF | avx2 x8 | 8 | 102.2 |
| i9-12900KF | shani | 16 | 142.0 |
| i9-12900KF | avx2 x8 | 16 | 136.6 |
| i9-12900KF | shani | 24 | 202.9 |
| i9-12900KF | avx2 x8 | 24 | 169.6 |

На что стоит обратить внимание:

1. **Multi-buffer — главный рычаг там, где нет SHA-NI**: 6.4× к скаляру на i7.
   Для сравнения: аналогичная реализация на Rust с крейтом `sha2` дала
   9.8 MH/s на том же i7 при 8 потоках.
2. **Аппаратная инструкция не выигрывает автоматически.** На выделенном
   P-ядре AVX2 обгоняет SHA-NI-ассемблер: asm упирается в латентность одного
   хеша, а AVX2 прячет её за 8 lanes.
3. **SMT меняет победителя.** SHA-NI получает от SMT ~66% (латентность),
   AVX2 — только ~34% (порты уже насыщены). Отсюда кроссовер на 16 потоках.
4. **Гибрид решает.** E-ядра Gracemont исполняют 256-битные операции в два
   прохода, но SHA-NI у них нативный — поэтому на полных 24 потоках
   выигрывает SHA-NI.

Именно поэтому автотюнинг меряет на вашем значении `-t`, а не пользуется
фиксированным списком приоритетов.

## Безопасность, приватность, закон

- В майнере **нет вшитого пула и нет вшитого адреса вознаграждения**. Оба
  параметра обязательны. Адрес в футере справки и в этом README — только
  для донатов, значением по умолчанию он не является нигде.
- Никаких приватных ключей, файлов кошелька, телеметрии; сетевых обращений
  нет никуда, кроме указанного вами пула.
- Запускайте только на своём железе или там, где у вас есть разрешение.
- Проверьте местное законодательство о майнинге и свой тариф на электричество.
- Не используйте CI-инфраструктуру (GitHub Actions и подобное) для запуска
  майнера.

## Известные ограничения

- Только Stratum v1; нет TLS, version rolling (`mining.configure`),
  `mining.set_extranonce` (в стиле NiceHash), роллинга `ntime`.
- SHA-NI-ассемблер использует двухпроходное расписание сообщений; слитное
  однопроходное было бы быстрее. Пулреквесты приветствуются.
- JSON-парсер минимальный, заточен под сообщения Stratum.
